## 5. 重要な仕様

### 5-1. 計算モデル

フロント（`index.html` の `calculateEDPI()`）と学習ジョブ（`train_model.py`）は**同一の関数形**を共有する。ここが崩れると学習が破綻するため、片方だけ変更してはいけない。

```
subTotal   = base_edpi × (1 + height_factor×(170 − 身長)
                            + 器用さ係数 + 腕の太さ係数 + マウス重量係数 + 支点係数)

finalEDPI  = subTotal × ダイナミクスカーブ(subTotal) × game_<title>_trim

インゲーム感度 = finalEDPI ÷ DPI × scale_<title>
（PUBG のみ対数変換：sens = clamp(round(50 + 25×log2(baseSens / 0.30)), 1, 100)）
```

| 要素 | 出どころ | 学習対象 |
| --- | --- | --- |
| `base_edpi` / 各係数 | `app_config` テーブル（フォールバック値は `index.html` 内） | ○ |
| ダイナミクスカーブ | `index.html` と `train_model.py` にハードコード | × |
| `scale_<title>` | エンジン固有の単位変換定数 | × |
| `game_<title>_trim` | `app_config`（既定 1.00） | ○ |

**ダイナミクスカーブ（実測ベースで確定済み・変更禁止）**

```
dev = (subTotal − 178.25) / 50
a   = atan(dev) / (π/2)

valo  : 1.00
apex  : 1.48 − 0.25 × a
ow    : 1.35 + 0.45 × a
fn    : 1.30 + 0.40 × a
delta : 1.08
cod   : 1.08
pubg  : 0.90
```

**単位変換スケール（`DEFAULT_SCALE`）**：valo 1.00 / apex 3.18 / ow 10.60 / fn 12.60 / delta 7.80 / cod 10.60 / pubg 1.00

**現在の係数（`index.html` のフォールバック値。実際は `app_config` が優先）**

```
base_edpi 230 / height_factor 0.005
器用さ    : 1:+0.25  2:+0.10  3:0.00  4:−0.08  5:−0.16
腕の太さ  : slim −0.04  normal 0.00  heavy +0.05
マウス重量: ultra −0.04  standard 0.00  mid +0.025  heavy +0.06  ultraheavy +0.10
支点      : wrist +0.40  arm 0.00  shoulder −0.12
```

### 5-2. 学習の仕様

**教師データの選別**（`train_model.py` 3-A）

| 種類 | メモ欄の値 | 学習に使う |
| --- | --- | --- |
| 診断フォームの「現在の感度」自動収集 | `自動学習収集データ` または `自動収集データ`（旧表記） | ○ |
| 感度メモタブからの保存 | 任意 | ○ |
| 診断結果そのものの保存 | `Long Cape Theory` | **×**（自己強化ループ防止） |

**しきい値**

| 定数 | 値 | 意味 |
| --- | --- | --- |
| `MIN_TOTAL_FOR_ANY` | 30 | これ未満は何もしない |
| `MIN_TOTAL_FOR_FULL` | 50 | これ以上でフェーズ2（全係数学習） |
| `MIN_ROWS_PER_LEVEL` | 5 | カテゴリ水準ごとの最小件数 |
| `MIN_ROWS_PER_GAME` | 20 | タイトル別補正の最小件数 |
| `TRIM_SHRINK_K` | 40 | 件数が少ないうち trim を 1.0 へ縮小する強さ |

**安全装置**：1 回の更新幅 ±10%（絶対最小ステップ併用）/ 絶対クランプ（`base_edpi` 120〜450、係数 −0.60〜0.90、trim 0.70〜1.30、eDPI 60〜800）/ タイトル別 IQR 外れ値カット / ボツ評価・ネガティブメモ・疎通テストデータの除外 / 同一ユーザー×同一タイトルは最終到達値のみ採用

**推定方法**：観測感度を不動点反復で `subTotal` に逆算 → 基準カテゴリ（普通 / 標準 / 肘）を 0 に固定した Ridge 回帰

### 5-3. データベース

`calc_logs`（診断ログ・感度メモ）と `app_config`（係数）の 2 テーブル。定義と RLS ポリシーは `supabase/schema.sql`。**本番へ適用済み。**

適用済みポリシー（`calc_logs`）：`自分のログのみ参照可（管理者は全件）` / `自分名義のログのみ追加可` / `自分のログのみ更新可`
`app_config`：`app_config は全員が読み取り可`（書き込みは service_role のみ）

**旧ポリシー 3 件は削除済み**（`Allow insert for all users` / `Allow select for own logs or anonymous` / `Users can update their own calc_logs`）。特に 2 つ目は未ログインで作成された行を誰にでも見せていた。

管理者判定は SQL 関数 `public.is_admin()`（JWT のメールアドレスを照合）。**ブラウザ側のメールアドレス判定は表示制御のみで、防御にはなっていない。**

## 6. 採用済み方針

- 学習モデルの関数形は、フロントの計算式と完全に一致させる
- 教師データは「ユーザー本人が申告した実使用感度」のみ。ツール自身の出力は学習しない
- 単位変換スケールとダイナミクスカーブは固定。学習が動かすのは `base_edpi`・各係数・`game_*_trim` のみ
- 感度は単位記号なしの数値文字列で DB に保存し、`%` などの単位は表示時に付ける
- 解説文はトップページに残す（折りたたみ表示）
- 依存パッケージはバージョン固定するが、**動作実績のある組み合わせを使う**

## 7. 却下／変更した方針

| 内容 | 結論 | 理由 |
| --- | --- | --- |
| 解説文を `about.html` へ全面移動 | **却下** | 広告掲載ページから本文が消え「価値の低い広告枠」判定のリスク。折りたたみ表示で代替 |
| 審査中はサイトを一切変更しない | **変更** | アクセス解析の追加は標準的で審査リスクが実質なく、計測なしの拡散は損失が大きい |
| 学習開始 10 件 | **変更（30 件へ）** | 動作確認データだけで `base_edpi` が最大 10% 動く危険があった |
| `base_edpi` を 230→239 に較正 | **保留** | 運営者判断。230 は「平均的な人」の基準値として妥当で、動かすと全ユーザーに影響 |
| `pivot_shoulder_factor` を −0.12→−0.08 | **保留** | 同上。根拠が 1 人分しかない |
| `supabase==2.10.0` へのバージョン固定 | **撤回** | 新形式 API キー（`sb_secret_...`）を JWT 形式検査で弾き、ジョブが失敗した |

## 16. 参考：収益試算の前提

集客施策の効果を見積もる際の計算式（1 セッションあたりの収益に分解してある）。

```
広告          = 1セッションあたりPV × RPM ÷ 1000
アフィリエイト = クリック率 × 購入率 × 平均注文額 × 紹介料率
課金          = 会員登録率 × 有料転換率 × 平均継続月数 × 月額
```

「標準」の仮定（月 5,000 セッション / PV 1.8 / RPM 250円 / クリック率 3% / 購入率 3% / 平均注文額 12,000円 / 紹介料率 2.5% / 登録率 4% / 有料転換率 0.5% / 月額 300円 / 継続 3か月）で、**月間約 4,500 円・訪問者 1 人あたり約 0.90 円**。月 10 万円には月 10 万セッションが必要。

**RPM も転換率もすべて仮定であり実測ではない。** アクセス解析を入れて実データが取れたら差し替えること。
